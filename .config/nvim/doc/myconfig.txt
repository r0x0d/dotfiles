1. BASICS                                                     *myconfig-basics*

Neovim has modes. The statusline shows which one you are in:

  🛸 NORMAL    move and run commands (the default, press <Esc> to get here)
  🚀 INSERT    typing text           (enter with  i  a  o)
  🌌 VISUAL    selecting text        (enter with  v  V  <C-v>)
  🛰️ COMMAND   after typing  :
  🪐 TERMINAL  typing into a terminal (see |myconfig-terminal|)

Survival keys (NORMAL mode):
  <Space>w      save                      <Space>q     quit window
  u / <C-r>     undo / redo               .            repeat last change
  dd  yy  p     delete line / copy line / paste
  /text <CR>    search     n / N  next / previous     <Esc>  clear highlight
  gcc           comment/uncomment line    gc (visual)  comment selection
  <C-h/j/k/l>   move between split windows
  -             open file explorer (oil). Edit names like text, then  :w
                to apply renames/deletes/new files. Press - again to go up.

Clipboard is shared with the system (yank in nvim, paste anywhere).
Relative line numbers: "5j" moves five lines down, "12dd" deletes twelve.

Look and feel ~
  Colorscheme: tokyonight "night" (lua/plugins/colorscheme.lua; swap it there).
  Rulers: thin vertical lines at columns 80 and 120. Help pages keep line
  numbers and rulers too; terminals and the dashboard hide them.
  Statusline: mode, git branch/changes, file, diagnostics, LSP emoji
  (legend in |myconfig-emoji|).

Needs ~
  wl-clipboard (Wayland) or xclip (X11) for the shared clipboard; macOS has it
  built in. A font with color emoji for the statusline (Noto Color Emoji on
  Linux, Apple Color Emoji on macOS).

2. TERMINAL (toggleterm)                                   *myconfig-terminal*

The key idea: a terminal is a *window onto a running shell*. You can HIDE the
window and the shell and everything in it keeps running. Show it again and
you are back where you left off. Closing the window does NOT kill the job.

THE ONE KEY TO REMEMBER ~
  <C-\>          toggle the terminal: show it if hidden, hide it if shown.
                 Works from NORMAL mode AND from inside the terminal.

Typical workflow ~
  1. <C-\>                 a floating terminal opens, you are typing in it
  2. cargo watch -x test   start a long-running command
  3. <C-\>                 hide it. The command keeps running in background.
  4. ...edit code...
  5. <C-\>                 show it again, output is still there

Opening other kinds of terminal ~
  <Space>ot      floating terminal (same as <C-\>)
  <Space>oh      terminal in a horizontal split at the bottom
  <Space>ov      terminal in a vertical split on the right
  <Space>og      lazygit in a float (needs `dnf install lazygit`)
  3<C-\>         terminal number 3. Each number is its own separate shell,
                 so 1<C-\>, 2<C-\>, 3<C-\> give you three independent
                 sessions, e.g. 1 = build, 2 = podman logs, 3 = scratch.

Running one command and keeping it around ~
  :Run cargo build
  :Run mock -r fedora-rawhide-x86_64 --rebuild foo.src.rpm
  :Run podman logs -f mycontainer
  (Terminals you open with <C-\> and <Space>o* start FISH. :Run commands go
  through bash, so write them in POSIX syntax, not fish syntax.)
  Opens a bottom terminal running that command. It stays open after the
  command finishes so you can read the output. Run the SAME :Run line again
  to toggle that same terminal (hide it, show it) instead of starting
  another. Tab completes command names.

Typing mode vs. looking mode ~
  Inside a terminal you are in TERMINAL mode: every key goes to the shell.
  To use Neovim keys (scroll, copy text, search) leave it first:
    <Esc><Esc>      go to NORMAL mode inside the terminal buffer
  Now you can scroll with <C-u>/<C-d>, search with /, yank with y.
  Press  i  to go back to typing in the shell.
  Note: <C-\><C-n> will NOT work as an escape here; use <Esc><Esc>.

Moving between windows from inside a terminal ~
  <Esc><Esc> first, then <C-h/j/k/l>.  Or just hide it with <C-\>.

Managing many terminals ~
  :TermSelect          pick a terminal from a list
  :ToggleTermToggleAll show or hide every terminal at once
  :ToggleTermSetName   give the current terminal a name (shows in the list)
  :TermExec cmd="ls"   send a command to the last terminal without opening it

Ending a terminal for real ~
  Hiding it (<C-\>)  -> shell and jobs KEEP RUNNING.        (what you want)
  :close or :q       -> window closes, jobs STILL RUNNING.
  Type  exit  or press <C-d> in the shell  -> the shell ends, terminal gone.
  <C-c>              -> interrupts the current command (like in any shell).
  Quitting Neovim (:qa) ends all terminals and their jobs.

Stuck? ~
  If the float seems frozen, you are probably in NORMAL mode inside it:
  press  i  to type again. If a hidden terminal "disappeared", try
  :TermSelect to list the ones still alive.

Needs ~
  fish (optional: without it the terminal uses your normal shell).
  lazygit for <Space>og: it is not in Fedora's repos; download the release
  binary from github.com/jesseduffield/lazygit or `brew install lazygit`.
  Loading: toggleterm loads the first time you use any key/command above.

3. FINDING THINGS                                              *myconfig-find*

  <Space>ff     find files by name         (Telescope)
  <Space>fg     search text in all files   (live grep)
  <Space>fb     switch open buffers
  <Space>fh     search the help pages
  <Space>fd     search diagnostics
  <Space>ft     search TODO/FIXME comments
  -             file explorer (oil)

Inside Telescope: type to filter, <C-n>/<C-p> move, <CR> open, <Esc> cancel,
<C-q> send results to the quickfix list.

Jumping inside a file: /text, then n/N; "gg" top, "G" bottom, "45G" line 45.
The context line pinned at the top shows which function/class you are in.

Needs ~
  ripgrep (`rg`) for <Space>fg live grep. fd (`fd-find`) makes file listing
  faster and is optional. make + a C compiler (gcc) to build the fzf matcher
  the first time. Telescope itself loads on first use.

4. CODE (LSP)                                                    *myconfig-lsp*

Active when the statusline shows server emoji (🐍 🧹 🦀 🐳 📄 🧾 📦 🐚 🌙 🧩).

  K              hover documentation
  gd             go to definition        (<C-o> to go back)
  gr             list references
  <Space>rn      rename symbol everywhere
  <Space>ca      code actions (quick fixes, imports, ...)
  <Space>lf      format the file (manual only, see |myconfig-dashboard|)
  <Space>e       show the diagnostic on this line in a float

Completion pops up while typing (blink.cmp):
  <C-Space> open   <C-n>/<C-p> next/previous   <C-y> accept   <C-e> close

Servers start when you open a file of their type (not at startup). Install
and update them with :Mason (they are installed automatically on first run).
.spec files use the system server `rpm_lsp_server` (see Needs below).

Rust is handled by rustaceanvim (it loads when you open a Rust file). Extra
commands:  :RustLsp runnables
:RustLsp debuggables  :RustLsp expandMacro  :RustLsp openCargo

Needs ~
  Language servers come from mason, which needs: git, curl, unzip, tar/gzip.
  node + npm for the yaml, json, docker and bash servers and for prettier.
  python3 with venv/pip for basedpyright and debugpy.
  cargo (Rust toolchain): compiles blink.cmp's fast fuzzy matcher, and
  rust-analyzer needs a cargo project. rust-analyzer comes from mason.
  .spec files: `sudo dnf install rpm-spec-language-server`.
  Completion works without the compiled matcher (Lua fallback + a warning).

5. DIAGNOSTICS AND TODOS                                       *myconfig-diag*

Signs in the left column:  🚨 error   🚧 warning   🛰️ info   💡 hint

  <Space>xx     all diagnostics in a panel (Trouble)
  <Space>xX     diagnostics of this file only
  <Space>xs     symbols outline of this file
  <Space>xr     LSP references in a panel
  <Space>xq     quickfix list
  <Space>xt     all TODO/FIXME comments in a panel
  ]t / [t       jump to next / previous TODO comment

Close a Trouble panel with  q . TODO keywords: TODO FIXME HACK NOTE WARN PERF.

Needs ~
  Nothing extra: diagnostics come from the language servers. :Trouble loads on
  first use; TODO highlighting loads when you open a file.

6. GIT                                                           *myconfig-git*

Gutter signs:  🌱 added   🍂 changed   🔥 deleted

  ]h / [h       next / previous changed hunk
  <Space>hp     preview the hunk       <Space>hs  stage hunk
  <Space>hr     reset (discard) hunk   <Space>hb  blame this line
  <Space>gd     open Diffview (all changes)
  <Space>gh     history of the current file
  <Space>gc     close Diffview

Pull requests (needs the `gh` CLI logged in):
  :Pr [n]        show the PR for this branch (or number n)
  :PrDiff [n]    show its diff in a new tab
  :Octo pr list  browse PRs and issues in Neovim

Needs ~
  git, for the gutter signs and branch info.
  gh (GitHub CLI), logged in with `gh auth login`, for :Pr, :PrDiff and :Octo.
  lazygit is optional (see |myconfig-terminal|).

7. DEBUGGING                                                   *myconfig-debug*

  1. Put the cursor on a line, press <Space>db to set a breakpoint.
  2. <F5> to start / continue. The debug UI opens by itself.
     Python: choose "Launch file". Rust: use :RustLsp debuggables.
  3. Step with <F10> over, <F11> into, <F12> out.

  <Space>dB     conditional breakpoint     <Space>de   evaluate expression
  <Space>du     toggle the debug UI        <Space>dr   debug REPL
  <Space>dl     re-run the last session

Variable values also appear inline next to your code (virtual text).
The UI closes automatically when the program ends.

Needs ~
  debugpy (Python) and codelldb (Rust/C): both installed by mason.
  Rust debugging needs `cargo build` output with debug info (the default
  profile has it). The debug plugins load on first use of <F5> or <Space>d*,
  and automatically when you open a Rust file.

8. TESTING                                                       *myconfig-test*

Python (pytest) and Rust (cargo test) through neotest:

  <Space>tt     run the test nearest the cursor
  <Space>tf     run all tests in this file
  <Space>td     DEBUG the nearest test (breakpoints work, see debugging)
  <Space>tl     run the last test again
  <Space>ts     toggle the summary tree of all tests
  <Space>to     show the output of the nearest test

Needs ~
  Python: pytest installed in the PROJECT's virtualenv (neotest finds
  .venv/ or venv/ in the project, or the active VIRTUAL_ENV).
  Rust: cargo; `cargo-nextest` is used automatically if installed.
  neotest loads the first time you press <Space>t*.

9. DATABASES                                                       *myconfig-db*

  <Space>D      open the database UI (dadbod)
  Press  A  in the UI to add a connection. URL examples:
    sqlite:/path/to/file.db
    postgresql://user@localhost/dbname
  Open a table or press  o  on a connection, write SQL in the buffer that
  appears, run it with  <Space>S  (whole buffer) or visual-select + <Space>S.
  SQL completion works through blink.

Needs ~
  sqlite3 for sqlite databases. For others the client must be installed:
  psql (`postgresql`), mysql/mariadb client. The UI loads on first use or when
  you open a .sql file.

10. WRITING MARKDOWN / BLOGS                                  *myconfig-writing*

  Markdown renders inline while you edit: headings, tables, code blocks and
  checkboxes look formatted. Move the cursor onto a line to see raw text.
  <Space>p      paste an image from the clipboard. It is saved under
                assets/images/ next to the file and a link is inserted.
                (Linux needs wl-clipboard; macOS needs `brew install pngpaste`)
  Turn spellcheck on for the buffer:  :setlocal spell   (]s / [s jump,
  z= suggests, zg adds a word)

Needs ~
  Clipboard images: wl-clipboard (Wayland) or xclip (X11); on macOS
  `brew install pngpaste`.
  Formatting Markdown with <Space>lf needs prettier (installed by mason).
  Rendering needs nothing extra. It loads when you open a Markdown file.

11. PLUGINS AND TOOLS                                          *myconfig-plugins*

  :PackUpdate    review and apply plugin updates (built-in vim.pack).
                 A buffer lists what changed; :w applies, :q cancels.
  :PackStatus    show plugin state without fetching anything
  nvim-pack-lock.json pins every plugin revision (keep it in git).
  Remove a plugin: delete it from lua/config/pack.lua, then
                 :lua vim.pack.del({"name"})
  :PluginGroups  which plugin groups are loaded right now, and what would
                 load the rest (see |myconfig-lazy|)
  :Mason         language servers/debuggers installer
  :MasonToolsUpdate   update everything mason manages
  :checkhealth   diagnose problems (try  :checkhealth vim.lsp)
  :messages      re-read recent messages and errors

Config lives in ~/.config/nvim:
  init.lua              entry point
  lua/config/           options, keymaps, lsp, icons, statusline
  lua/config/pack.lua   the list of plugins (vim.pack) and build hooks
  lua/plugins/          one file per topic: the setup() call of each plugin.
                        Add a plugin = add it to pack.lua + call its setup
  doc/myconfig.txt      this file (run :helptags ALL after editing it)

Needs ~
  git (vim.pack clones plugins with it) and Neovim 0.12 or newer.
  treesitter parsers compile with a C compiler: gcc, make, and the
  tree-sitter CLI (`sudo dnf install tree-sitter-cli`).

13. LOST? RECOVERY TRICKS                                         *myconfig-lost*

  Pressing keys does weird things   -> <Esc> a couple of times
  Can't type in a terminal          -> press  i
  Can't leave a terminal            -> <Esc><Esc>  (or <C-\> to hide it)
  Weird split/panel won't go away   -> :only   (keep just this window)
  Accidentally changed something    -> u  (undo)   :e!  (reload from disk)
  Want to quit without saving       -> :q!         (all: :qa!)
  A panel (Trouble, help, ...)      -> press  q
  Forgot a mapping                  -> press <Space> and read which-key
  Forgot a command                  -> :Telescope commands
  Anything else                     -> :Telescope help_tags  (<Space>fh)

14. DASHBOARD, SESSIONS, FORMAT                            *myconfig-dashboard*

Dashboard ~
  Opens when you start `nvim` with no file. It shows:
    Sessions   your most recent saved sessions (directory and git branch)
    Projects   git projects you opened recently
    Recent     recent files (of this project if you are in one)
    Actions    find file, grep, explorer, new file, update plugins, Mason, help, quit
    Footer     nvim version, plugins loaded out of installed, time to UI,
               session and recent-file counts, and git branch + changed
               files of the current directory (🌿 branch 🍂 changed 🌱 clean)
  Pick an entry: press its number, or type the first letters of an action
  (f = Find file, g = Grep, q = Quit ...) then <CR>. Move with <C-n>/<C-p>.
  The "-" key is NOT captured here: it still opens the file explorer.
  <Space>;       bring the dashboard back at any time

  Choosing a PROJECT changes into it and restores its session if one exists,
  otherwise it opens the file finder there.

Sessions (persistence.nvim) ~
  A session (open files, windows, tabs) is saved automatically for each
  directory (and git branch) when you quit Neovim. Nothing to remember.
  <Space>sr      restore the session of the current directory
  <Space>sl      restore the most recent session, any directory
  <Space>ss      pick a session from a list
  <Space>sd      do NOT save a session when quitting this time
  Sessions live in ~/.local/state/nvim/sessions/. Delete a file there to
  forget one.

Formatting (conform.nvim) ~
  Formatting is MANUAL. Nothing is rewritten when you save.
  <Space>lf      format the file (or the visual selection)
  :Format        same; works with a range, e.g.  :10,20Format
  :ConformInfo   show which formatter applies to this file and if it is found
  Formatters: python ruff (imports + format), rust rustfmt, lua stylua,
  sh/bash shfmt, fish fish_indent, toml taplo, yaml/json/markdown prettier.
  Anything else falls back to the language server's formatter.
  rustfmt comes from the system:  sudo dnf install rustfmt

Needs ~
  git, for the branch/changes line of the dashboard and project detection.
  Formatters: ruff (mason), stylua, shfmt, prettier, taplo (all mason),
  fish_indent (ships with fish), rustfmt (`sudo dnf install rustfmt`).
  Missing formatters are skipped and the LSP formats instead.

15. REQUIREMENTS (EXTERNAL TOOLS)                       *myconfig-requirements*

>
  sudo dnf install git gh ripgrep fd-find make gcc tree-sitter-cli \
    nodejs npm python3 python3-pip unzip curl cargo rustfmt rust-analyzer \

>
  brew install neovim git gh ripgrep fd tree-sitter-cli node python \
    sqlite fish pngpaste lazygit rust
<

Installed for you by :Mason on first run (no action needed): basedpyright,
ruff, rust-analyzer, dockerfile/yaml/json/bash/lua language servers, taplo,
shfmt, stylua, prettier, codelldb, debugpy. Check them with :Mason.

Which tool a feature needs is listed under "Needs" at the end of each section.
Missing tools never break startup; the feature just says so or is skipped.

16. STARTUP AND LAZY LOADING                                      *myconfig-lazy*

Plugins are managed by the built-in vim.pack and loaded on demand so that
starting Neovim stays fast (about 30 ms of config time). What loads when is
declared in lua/config/groups.lua. Run  :PluginGroups  to see the live state.

  Always at startup    colorscheme, treesitter, file explorer (oil), mason PATH
  Right after startup  which-key, mason tool installer
  Opening a file       git signs, indent detection, treesitter-context,
                       TODO highlighting, session saving, completion (blink),
                       LSP servers
  Insert mode / : line completion (blink) if not already loaded
  Rust file            rustaceanvim + the debug plugins
  Markdown file        markdown rendering
  SQL file             database plugins and SQL completion
  First use of ...     :Telescope  :Trouble  :Diffview*  :Octo  :Format
                       :PasteImage  :ToggleTerm / :Run / <C-\>  :DBUI
                       <F5> and <Space>d*  (debugging)
                       <Space>t*           (tests)
                       <Space>;            (dashboard)
  No file given        the dashboard, plus session list

Python and container (Containerfile, compose) files need no plugin of their
own: their language servers start per filetype and debugpy/pytest load with
the debug and test groups when you use them.

The first use of an on-demand feature in a session is a few milliseconds slower
(the plugin loads then). Tab-completion of  :Telescope <Tab>  works only after
it has loaded once.

Add a plugin: list it in lua/config/pack.lua (mark it lazy), then give it a
group in lua/config/groups.lua with a trigger and a setup file in lua/plugins/.
